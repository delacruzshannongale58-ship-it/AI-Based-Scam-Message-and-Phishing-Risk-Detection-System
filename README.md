# ScamScan – AI-Based Scam Message and Phishing Risk Detection System

Browser-only web app (HTML, CSS, JavaScript). No server needed, so it works in Spck and on GitHub Pages.

## Files
| File | Purpose |
|---|---|
| index.html, style.css, app.js | Interface: paste / upload / text input, OCR, result screen |
| engine.js | Text preprocessing, TF-IDF + Logistic Regression prediction, scam-indicator rules, risk scoring |
| model.js | Trained model weights (generated by train_model.py) |
| train_model.py | Trains the model on a dataset and exports model.js + metrics.json |
| starter_data.csv | 86 hand-written messages used ONLY to make the starter model |
| test_engine.js | Optional Node test of the engine |

## Run it in Spck
1. Put all files in one folder (project) in Spck.
2. Open index.html with Spck's built-in preview / browser.
3. Paste a screenshot (Paste image button, or long-press the text box and paste) or type a message.
The screenshot reader (Tesseract.js) loads from the internet the first time, so you need data/Wi-Fi.

## Publish it (Application URL for the instructor)
1. Push the folder to a GitHub repository from Spck.
2. On GitHub: Settings -> Pages -> Deploy from branch -> main / root.
3. Your Application URL will be https://YOUR-USERNAME.github.io/REPOSITORY-NAME/
Open it on your phone and test before submitting.

## IMPORTANT: replace the starter model with a real one
The included model.js was trained on only 86 hand-written messages so the app can run. Its numbers are NOT real
performance results and must NOT go in your documentation. To train the real model:
1. Get the UCI SMS Spam Collection (file "SMSSpamCollection") and a phishing message CSV (text + label columns).
2. In Google Colab: upload train_model.py and the dataset files, then run
       !python train_model.py --data SMSSpamCollection phishing.csv --out .
   (if your CSV columns have unusual names add --text-col NAME --label-col NAME)
3. Download the new model.js and replace the old one in your project. Keep engine.js unchanged.
4. Copy the REAL numbers printed by the script (and saved in metrics.json) into Tables 2, 11, 12 of your documentation.
5. Push to GitHub again.
